# Event discovery map

The map uses the existing `feed.ranked` query, including its interest ranking, single filter, shared profile center, and radius. It shows at most the query's top 60 results, not all events in a viewport. Panning never mutates the profile, prompts for permission, or issues feed queries. Explicit city/current-location and radius changes update the same profile used by Feed. Coordinates are public event coordinates only; missing/invalid coordinates are never replaced with a city centroid. Exact overlapping coordinates share a counted marker; tapping cycles the events, and the numbered selector reaches every rendered event. Single locations render as a category-coloured pin with the same event-type icon used on feed cards and event detail (`components/event-type-icon.tsx`). Nearby locations merge into a counted blue cluster whose radius is about 46 screen pixels at the current zoom (`clusterGroups`); tapping a cluster zooms to its bounds. The selected marker grows and gets an ink ring.

## Providers and builds

- iOS: Apple Maps via `react-native-maps` 1.29.11, the version recommended by [Expo SDK 58](https://docs.expo.dev/versions/v58.0.0/sdk/map-view/). No Google provider or paid key is configured. Apple legal attribution remains unobscured. A new native binary must include this native dependency; an OTA-only update of an older binary is insufficient.
- Web: Leaflet 1.9.4 (BSD-2-Clause) and OpenStreetMap standard raster tiles. Attribution links to OSM's copyright/ODbL notice. Only visible tiles are requested, with no offline/prefetch feature, no proxy, normal browser Referer/User-Agent and HTTP caching. Tile failures retain the accessible event selector. See the [tile usage policy](https://operations.osmfoundation.org/policies/tiles/); public tiles have no SLA and should be replaced by a suitable hosted provider before substantial traffic.
- Android: deliberate, labeled event-selector/card fallback and external OpenStreetMap links. This build does not mount an unconfigured Google Map. Full native Android maps require a restricted Maps SDK for Android key, Expo config plugin setup and a rebuilt binary; no credential is requested for this fallback.

No background location, friend tracking, attendee data, geocoding requests, or map-provider scraping. Current location is requested only on button press, using the existing foreground-only Bay Area location helper. Manual city selection works without permission. A gold dot marks locations with at least one saved event (within the existing saved-list query's 100-item cap).

The new Revyl scenario is a definition only, not proof of a native run. It requires a newly built iOS binary and seeded events with public coordinates. Browser evidence and native verification limitations are recorded with the PR.
